# Changelog

All notable changes to this project will be documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.0.0/),
and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

Only the version in flight is written out in full. A released version keeps its
heading and its link -- the entries live in the GitHub release for its tag,
which is where anyone comparing two deployments will look. This file stays
short enough to read in one screen.

## [2.0.0] - unreleased
**Upgrading:** a plan regenerated for an existing cluster can differ. Service ranges shrink from /16 to /20 (/18 for hyperscale), hyperscale pods for a `10.x` VPC move from `172.16.0.0/13` to `172.24.0.0/13`, EKS micro and standard gain a second subnet of each type, and GKE and AKS subnets drop `availabilityZone`. EKS and AKS cannot change a cluster's service range, and Terraform replaces a cluster whose service range changes. If your configuration fetches plans at plan time, pin the values you deployed, or pass `servicesCidr` and `podsCidr` with your current ranges.

### Changed (API output)
- **Nodes, control plane, pods and services are separate in every tier.** Each plan now has one control-plane network (`subnets.controlPlane`, type `control-plane`) beside the public and node subnets: a /28 for GKE (`master_ipv4_cidr_block`), AKS (the API server VNet-integration subnet) and generic Kubernetes (control-plane nodes, so a floating API server address can move between them). EKS gets one /27 split into two /28s in two AZs for `vpc_config.subnet_ids`, because EKS rejects a single subnet; AWS advises naming only two so you control where its network interfaces land. Subnets are placed first-fit at offsets aligned to their size, so the control plane fills the gap between public and node subnets and only EKS micro and standard need a larger VPC. Pods and services stay outside the VPC, each in its own RFC 1918 block, and every finished plan is checked to have no overlapping ranges.
- **EKS plans span at least two AZs in every tier.** EKS refuses cluster subnets in a single AZ, and internet-facing ALBs need public subnets in two, but micro and standard put one public and one private subnet in `us-east-1a`. They now get two of each subnet type, which needs a /23 VPC (micro) or /22 (standard).
- **GKE and AKS subnets carry no zone.** GCP and Azure subnets span every zone in their region; node pools choose zones. The `us-central1-a` and `eastus-1` style values were never valid for a subnet (and `eastus-1` is not how Azure names zones).
- **Service ranges are right-sized**: /20 (4,096 ClusterIPs, the size GKE uses by default), or /18 for hyperscale (16,384, above Kubernetes' tested limit of 10,000 services). A /16 took the whole of `192.168.0.0/16`, so any connected `192.168.x.x` network collided with it.
- **Generated pod and service ranges avoid `172.17.0.0/16`**, Docker's default bridge network, which AWS also reserves for some services. Hyperscale pods for a `10.x` VPC were `172.16.0.0/13`, which contains it; they are now `172.24.0.0/13`. A VPC that overlaps it is still accepted, with a new `warnings` entry in the plan.
- **`minVpcPrefix` is computed from the actual layout**, per provider. Enterprise was listed as /18 but fits a /19. `GET /api/k8s/tiers?provider=eks` returns EKS's layout; tier objects now include `controlPlaneSubnets` and `controlPlaneSubnetSize`.
- **The hyperscale description states its real capacity.** "50-5000 nodes ... (EKS/GKE max)" is now: the /13 pod range holds 2,048 nodes at a /24 per node (AKS overlay always; GKE at 65-128 max pods per node), and 5,000 nodes needs GKE max pods per node of 32 or fewer, or a /11 `podsCidr`.
- **A too-small VPC error names the minimum**, e.g. "its subnets need 416 addresses (a /23 or larger)".
- **`metadata.version` is `2.0`.**

### Fixed
- **A VPC CIDR that spills out of private space is rejected.** The private-range check looked only at the first address, so `10.0.0.0/7`, `172.16.0.0/11` and `192.168.0.0/15` passed even though they reach into public addresses. `10.0.0.0/0` passed too, was normalized to `0.0.0.0/0`, and produced subnets in public space. The whole range must now sit inside one RFC 1918 block.
- **Auto-generated `192.168.x.x` VPCs are valid CIDRs.** With no `vpcCidr`, picking the 192.168 block chose a random third octet, giving ranges like `192.168.37.0/18`: host bits set, and anything from `192.168.193.0/18` up ran past `192.168.255.255` into public `192.169.x.x`. Every subnet inherited the misalignment. Generated VPCs are now /18-aligned inside their block.
- **Malformed CIDRs are rejected instead of truncated.** `10.0.0.0/16abc` and `10.0.0.1x/16` were accepted as `10.0.0.0/16`, because `parseInt` stops at the first non-digit. Octets and prefixes must now be digits only.
- **The calculator works over plain HTTP.** Subnet ids came from `crypto.randomUUID()`, which browsers expose only on HTTPS and localhost, so on `http://<LAN address>` every Calculate failed with "Failed to calculate subnet". Ids are now a page-local counter.
- **A saved dark theme is honored.** The calculator went dark only when the saved choice was dark *and* the operating system was dark. The saved choice now wins, the same rule the API docs page uses.
- **Examples match what the API returns.** The README, OpenAPI examples and `docs/` showed services in `10.2.0.0/16` and pods in `10.1.0.0/16` (the API never emits either), subnets outside the requested VPC, invalid CIDRs such as `10.0.3.0/21`, and a zone named `default-a`. They are regenerated from the generator. The hyperscale tier's pod-capacity note is corrected: a /13 holds 2,048 nodes at 110 pods per node; 5,000 nodes needs 32 or fewer.
- **The EKS docs no longer suggest adding `pods.cidr` to the VPC.** The Terraform for VPC CNI custom networking associated `pods.cidr` as a secondary VPC CIDR, which AWS always refuses: the API puts pods in a different RFC 1918 block than the VPC, AWS forbids mixing RFC 1918 blocks in one VPC, and secondary blocks must be /16 to /28. `pods.cidr` is for an overlay CNI (Calico, Cilium); the example now uses a `100.64.0.0/10` block for custom networking.
- **The OpenAPI schema matches the server's validation, and is valid.** `vpcCidr` was checked only for a private-looking prefix; `region`, `vpcCidr` and `deploymentName` now carry the same pattern and length limits the API enforces. The `region` property also used an `examples` map, which OpenAPI 3.0 doesn't allow in a schema, so the document failed validation; it now uses a single `example`.
- **The API docs page (`/api/docs/ui`) renders correctly in both themes.** In light mode the GET and POST badges had dark text on blue and green, and the request URL and response headers after "Execute" were white on a light background. The copy-to-clipboard icons were blank squares in both themes, because a style override erased the icon. Schema properties lost their types, with every `[...]` toggle pushed to the far right. The Servers card was wider than the cards around it, the API title and description appeared twice, `/favicon.ico` returned 404, "Controls Accept header." was dark green on dark, and focus outlines were removed, so keyboard users couldn't see where they were.
- **Text meets WCAG AA contrast (4.5:1) in both themes.** Three pairs fell short: secondary text in light mode (4.49:1 on the page background, less on the footer), validation errors in dark mode (3.6:1, red on the dark card), and button and badge text in dark mode (3.6:1, white on light blue). Light-mode `--muted-foreground` is slightly darker, dark-mode `--destructive` is a lighter red, and dark-mode text on primary and destructive surfaces is now dark, in the app and on the API docs page. `tests/unit/ui-styles.test.ts` reads the colors from `index.css` and checks every text pair the app renders; it used to check hard-coded values, one of which didn't match the stylesheet, and the design docs quoted ratios (7.2:1, 12.5:1) the palette never had.
- **Dismissed toasts leave memory after a second**, not 16 minutes.

### Security
- **The build no longer depends on `braces`.** A high-severity advisory (GHSA-vfj7-8cjw-p6xm, stack exhaustion from deeply nested patterns) covers every published version of `braces`, which Tailwind CSS 3 pulled in through its file watcher and glob libraries, so `npm audit` failed with no patch to apply. Tailwind CSS 4 doesn't use it. Only build tooling was affected; neither shipped bundle contained it.
- **The web app no longer allows scripts from cdn.jsdelivr.net.** jsDelivr serves any npm package or GitHub file, so allowing it on every page let an injected `<script>` load arbitrary code despite `script-src 'self'`. Only the Swagger UI page (`/api/docs/ui`) allows it now. `connect-src` also drops the Google Fonts origins, which it never needed.
- **Swagger UI assets are pinned and integrity-checked.** The page loaded the floating `swagger-ui-dist@5` tag with no integrity check. It now loads `5.33.1` with sha384 Subresource Integrity, so a changed CDN file is refused.
- **The API is rate limited.** `/api` routes allow 100 requests per minute per IP and answer `429` with `{"code": "RATE_LIMITED"}` and `RateLimit-*` headers. Health checks (`/health*`, `/api/v1/health*`) are exempt so probes never fail. Before, plan generation had no limit.
- **Request input is bounded.** Bodies are capped at 16 KB (was 100 KB). `region` must be lowercase letters, digits and hyphens (64 characters at most), since it is written into zone names that end up in Terraform; `deploymentName` is capped at 128 characters. A request with `"region": "US-EAST-1"` now gets a 400.
- **500 responses no longer echo internal error messages.** The global error handler returned `err.message` for every failure. Client errors (malformed JSON, oversized bodies) are now logged as warnings, not errors.
- **The dev server's DNS-rebinding protection is back on.** `allowedHosts: true`, needed only for Replit's proxied hostnames, turned off Vite's Host header check.
- **The package is marked `private`**, so it cannot be published to npm by accident.

### Added
- **Private network mode** (`"networkMode": "private"`). The plan has no public subnets; `subnets.loadBalancer` holds internal load-balancer subnets instead, and egress is expected through a managed NAT or gateway that takes no space in the layout. GKE gets one regional proxy-only subnet (`REGIONAL_MANAGED_PROXY`, needed for internal Application Load Balancers and the internal Gateway; one per region and network, /26 minimum) and Cloud NAT for egress. AKS gets one regional internal load-balancer subnet and a NAT gateway or user-defined routes for egress. EKS gets internal load-balancer subnets in at least two AZs (tag `kubernetes.io/role/internal-elb`), and reaches the internet through a transit gateway to an egress VPC, or not at all with VPC endpoints: a public NAT gateway needs a public subnet, and a private one can't reach the internet. Plans now always include `networkMode` and `subnets.loadBalancer` (empty in public mode), and `/api/k8s/tiers` takes `?networkMode=`.
- **`podsCidr` and `servicesCidr` request fields.** Every plan whose VPC is in the same RFC 1918 block got identical pod and service ranges, so a second cluster in the same GCP network (where secondary ranges must not collide), or in a peered network, overlapped the first. Supply your own ranges to keep clusters apart or to keep an existing cluster's service range. Pods may use RFC 1918 or `100.64.0.0/10` at /8 to /24; services RFC 1918 at /13 to /24 (EKS allows /12-/24, AKS requires smaller than /12). Neither may overlap the VPC, each other, or `172.17.0.0/16`.
- **`availabilityZones` request field.** Generated EKS zone names follow `{region}{letter}`, but which letters exist varies by region and account: `ap-northeast-1b` doesn't exist for new accounts. Pass the zones your account has (e.g. from `data.aws_availability_zones`); they are assigned round-robin. EKS needs at least two; GKE and AKS reject the field because their subnets are regional.
- **`warnings` in the plan**, listing non-fatal issues such as a VPC that overlaps `172.17.0.0/16`. Omitted when empty.
- **`provider` query parameter on `/api/k8s/tiers`.**
- **`HOST` environment variable.** Production now binds `0.0.0.0` by default, so the server is reachable inside a container; development binds `127.0.0.1`. Set `HOST` to override either.
- **CI checks the production build, not just the source.** `npm run smoke` (`scripts/smoke-test.ts`) starts `dist/index.cjs` and checks it over HTTP: health and version, the web app with its CSP and caching headers, the SPA fallback, the plan and tiers APIs (private mode, validation errors, rate-limit headers), and the API docs page's pinned assets. CI then validates the served OpenAPI document with `swagger-cli`, which would have caught the invalid `region` schema this release fixes. The CI job also has a 15-minute timeout.
- **OpenAPI examples are generated by the API itself** at startup, and a test checks each one against a live request, so they can't drift from real output again.

### Changed (project)
- **The API docs page uses the web app's palette and fonts.** One set of color tokens, copied from the app and redefined for dark mode, replaces separate light and dark style sheets that had drifted apart (the version badges even swapped colors between themes). A test fails if the page stops matching the app. Method badges use fixed, readable colors, operations carry a method-colored edge, and text is Inter and JetBrains Mono, as in the app. Toggling the theme re-renders the page in place instead of reloading it. The page now lives in `server/swagger-ui.ts`, taking about 1,100 lines out of `server/routes.ts`, and operations have explicit `operationId`s, so deep links such as `#/Kubernetes/generateNetworkPlan` work without Swagger deprecation warnings.
- **Tailwind CSS 4, through its Vite plugin.** Tailwind's Rust engine (Oxide to scan sources, Lightning CSS to add prefixes and minify) replaces the PostCSS and autoprefixer pipeline. The theme moves from `tailwind.config.ts` into `client/src/index.css` (`@theme inline`), and `tw-animate-css` replaces the `tailwindcss-animate` plugin. The calculator looks the same: computed styles of 18 elements in both themes match before and after, apart from one fix. The Calculate and Reset buttons now line up with the input at 48px. They were 56px and started 8px above it, because Tailwind 3's `space-y` added a margin before the input's hidden label, and they stretched further when a validation error showed. The CSS bundle grows from 33.6 to 42.7 KB (7.1 to 8.6 KB gzipped), from v4's registered custom properties and theme variables.
- **The package is named `subnet-splitter`** (was the template's `rest-express`), at version 2.0.0. `/health`, `/api/version` and the OpenAPI document report the version from `package.json` instead of a hard-coded `1.0.0`.
- **Validation errors name the field.** A bad request answers `"Invalid request: deploymentSize: Required"` instead of a JSON dump of the validator's issue list.
- **Generated VPCs vary more.** A random VPC can be any aligned /18 in its block, not only `10.N.0.0/18` or `172.N.0.0/18`.
- **The web app downloads less.** JavaScript is 271 KB (88 KB gzipped), down from 371 KB (116 KB), and the unused Fira Code font is no longer requested.
- **`npm start` runs `node dist/index.cjs`**, which works in cmd and PowerShell as well as POSIX shells. The build already bakes in `NODE_ENV=production`.
- **Logs are quieter.** Health probes and response bodies are no longer logged per request, and startup lists routes at debug level.

### Removed
- **Replit support**: `.replit`, the three `@replit/vite-plugin-*` dev plugins, the Replit CSP origins, `REPL_ID` handling, the `@assets` alias, and the `127.0.0.1`-then-`localhost` bind fallback.
- **Unused dependencies**: `react-hook-form`, `@hookform/resolvers`, `wouter`, `@radix-ui/react-label` and `cross-env` (29 packages leave the install). The calculator's single input no longer needs a form library, and its two pages no longer need a router.
- **The API docs page's repaint script and 268 KB topbar preset.** A MutationObserver re-applied inline colors after every render and click; Swagger's own light and dark highlight themes now do that job. The page no longer downloads `swagger-ui-standalone-preset.js`, whose topbar it hid anyway.
- **The Tailwind CSS 3 toolchain**: `postcss`, `autoprefixer`, `tailwindcss-animate`, `tailwind.config.ts` and `postcss.config.js`, plus theme tokens nothing used (chart, sidebar and status colors, accordion animations, the toggle-elevate classes, and shadow, radius and spacing variables the old config never read).
- **The `test:ui` script**, which needed `@vitest/ui` and never worked. Also unused code: `server/storage.ts` and the `form` and `label` components.
