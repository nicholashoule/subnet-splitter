# Changelog

All notable changes to this project will be documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.0.0/),
and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

Only the version in flight is written out in full. A released version keeps its
heading and its link -- the entries live in the GitHub release for its tag,
which is where anyone comparing two deployments will look. This file stays
short enough to read in one screen.

## [2.0.0] - unreleased
**Upgrading:** a plan regenerated for an existing cluster can differ. Service ranges shrink from /16 to /20 (/18 for hyperscale), hyperscale pods for a `10.x` VPC move from `172.16.0.0/13` to `172.24.0.0/13` (to `100.64.0.0/13` for AKS), EKS micro and standard gain a second subnet of each type, and GKE and AKS subnets drop `availabilityZone`. VPCs larger than /16, AKS ranges in `172.30.0.0/16` or `172.31.0.0/16`, and blank (`""`) CIDR fields are now rejected. EKS and AKS cannot change a cluster's service range, and Terraform replaces a cluster whose service range changes. If your configuration fetches plans at plan time, pin the values you deployed, or pass `servicesCidr` and `podsCidr` with your current ranges.

### Changed (API output)
- **Every error body is `{"error", "code"}`.** 1.0 answered a malformed or oversized body, and any unexpected failure, with `{"message": ...}` carrying the parser's or the exception's text. Those responses now carry `error` with fixed text ("Request body is not valid JSON", "Internal Server Error") and a `code` (`INVALID_REQUEST`, `INTERNAL_ERROR`), like the plan route's own errors always did. A client that reads `message` must read `error`.
- **Nodes, control plane, pods and services are separate in every tier.** Each plan now has one control-plane network (`subnets.controlPlane`, type `control-plane`) beside the public and node subnets: a /28 for GKE (`master_ipv4_cidr_block`), AKS (the API server VNet-integration subnet) and generic Kubernetes (control-plane nodes, so a floating API server address can move between them). EKS gets one /27 split into two /28s in two AZs for `vpc_config.subnet_ids`, because EKS rejects a single subnet; AWS advises naming only two so you control where its network interfaces land. Subnets are placed first-fit at offsets aligned to their size, so the control plane fills the gap between public and node subnets and only EKS micro and standard need a larger VPC. Generated pods and services stay outside the VPC, each in its own block (RFC 1918, or `100.64.0.0/10` for pods when no RFC 1918 block has room), and every finished plan is checked to have no overlapping ranges.
- **EKS plans span at least two AZs in every tier.** EKS refuses cluster subnets in a single AZ, and internet-facing ALBs need public subnets in two, but micro and standard put one public and one private subnet in `us-east-1a`. They now get two of each subnet type, which needs a /23 VPC (micro) or /22 (standard).
- **GKE and AKS subnets carry no zone.** GCP and Azure subnets span every zone in their region; node pools choose zones. The `us-central1-a` and `eastus-1` style values were never valid for a subnet (and `eastus-1` is not how Azure names zones).
- **Service ranges are right-sized**: /20 (4,096 ClusterIPs, the size GKE uses by default), or /18 for hyperscale (16,384, above Kubernetes' tested limit of 10,000 services). A /16 took the whole of `192.168.0.0/16`, so any connected `192.168.x.x` network collided with it.
- **Generated pod and service ranges avoid `172.17.0.0/16`**, Docker's default bridge network, which AWS also reserves for some services. Hyperscale pods for a `10.x` VPC were `172.16.0.0/13`, which contains it; they are now `172.24.0.0/13` (`100.64.0.0/13` for AKS, below). A VPC that overlaps it is still accepted, with a new `warnings` entry in the plan.
- **`minVpcPrefix` is computed from the actual layout**, per provider. Enterprise was listed as /18 but fits a /19. `GET /api/k8s/tiers?provider=eks` returns EKS's layout; tier objects now include `controlPlaneSubnets` and `controlPlaneSubnetSize`.
- **The hyperscale description states its real capacity.** "50-5000 nodes ... (EKS/GKE max)" is now: the /13 pod range holds 2,048 nodes at a /24 per node (AKS overlay always; GKE at 65-128 max pods per node), and 5,000 nodes needs GKE max pods per node of 32 or fewer, or a /11 `podsCidr`.
- **AKS plans stay clear of the ranges AKS reserves.** AKS reserves `172.30.0.0/16` and `172.31.0.0/16` for every cluster's virtual network, pod and service ranges, and rejects a pod CIDR that overlaps them. In 1.0 a generated VNet could land in them, and a `vpcCidr`, `podsCidr` or `servicesCidr` there was accepted. AKS plans now never generate these ranges, a generated VNet avoids them, and a caller range that overlaps them is rejected. Every /13 left in `172.16.0.0/12` contains either `172.17.0.0/16` or an AKS-reserved range, so hyperscale AKS pods for a `10.x` VNet come from `100.64.0.0/13` (RFC 6598 shared space, which AKS overlay supports for pods).
- **Generated pods fall back to `100.64.0.0/10`** when no RFC 1918 block outside the VPC has room, instead of failing. EKS, GKE and AKS all accept RFC 6598 space for pods. Generated pods also keep out of the RFC 1918 block of a caller's `servicesCidr`, as generated services already kept out of the pods' block.
- **Provider limits are enforced.** A GKE `servicesCidr` must be /16 to /24: Google caps user-managed Services ranges at /16, and /13 to /15 were accepted. Every VPC must be /16 or smaller: for EKS that is AWS's own limit (VPC CIDR blocks are /16 to /28); for GKE, AKS and generic Kubernetes it is this project's standard (GCP subnets and Azure VNets may be larger). A `10.0.0.0/8` or `172.16.0.0/12` VPC was accepted before.
- **A too-small VPC error names the minimum**, e.g. "its subnets need 416 addresses (a /23 or larger)".
- **`metadata.version` is `2.0`.**

### Fixed
- **A VPC CIDR that spills out of private space is rejected.** The private-range check looked only at the first address, so `10.0.0.0/7`, `172.16.0.0/11` and `192.168.0.0/15` passed even though they reach into public addresses. `10.0.0.0/0` passed too, was normalized to `0.0.0.0/0`, and produced subnets in public space. The whole range must now sit inside one RFC 1918 block.
- **Auto-generated `192.168.x.x` VPCs are valid CIDRs.** With no `vpcCidr`, picking the 192.168 block chose a random third octet, giving ranges like `192.168.37.0/18`: host bits set, and anything from `192.168.193.0/18` up ran past `192.168.255.255` into public `192.169.x.x`. Every subnet inherited the misalignment. Generated VPCs are now /18-aligned inside their block.
- **A blank CIDR is rejected instead of read as "generate one".** An empty `vpcCidr` counted as omitted, so `"vpcCidr": ""` from an unset Terraform variable silently got a random VPC, a different one on each request. The new `podsCidr` and `servicesCidr` fields, and whitespace-only values once input was trimmed, would have done the same. A blank value in any of the three now gets a `400`; omit the field to have a range generated.
- **Malformed CIDRs are rejected instead of truncated.** `10.0.0.0/16abc` and `10.0.0.1x/16` were accepted as `10.0.0.0/16`, because `parseInt` stops at the first non-digit. Octets and prefixes must now be digits only.
- **The calculator works over plain HTTP.** Subnet ids came from `crypto.randomUUID()`, which browsers expose only on HTTPS and localhost, so on `http://<LAN address>` every Calculate failed with "Failed to calculate subnet". Ids are now a page-local counter.
- **A saved dark theme is honored.** The calculator went dark only when the saved choice was dark *and* the operating system was dark. The saved choice now wins, the same rule the API docs page uses.
- **Examples match what the API returns.** The README, OpenAPI examples and `docs/` showed services in `10.2.0.0/16` and pods in `10.1.0.0/16` (the API never emits either), subnets outside the requested VPC, invalid CIDRs such as `10.0.3.0/21`, and a zone named `default-a`. They are regenerated from the generator. The hyperscale tier's pod-capacity note is corrected: a /13 holds 2,048 nodes at 110 pods per node; 5,000 nodes needs 32 or fewer.
- **The EKS docs no longer suggest adding `pods.cidr` to the VPC.** The Terraform for VPC CNI custom networking associated `pods.cidr` as a secondary VPC CIDR, which AWS always refuses: the API puts pods in a different RFC 1918 block than the VPC, AWS forbids mixing RFC 1918 blocks in one VPC, and secondary blocks must be /16 to /28. `pods.cidr` is for an overlay CNI (Calico, Cilium); the example now uses a `100.64.0.0/10` block for custom networking. The docs also said pods "get IPs via AWS VPC CNI (secondary ranges)" and that hyperscale's `/20` node subnets gave "ample Node + Pod headroom" for 5,000 nodes. Under the default VPC CNI, pods share the node subnets, which hold at most 2 nodes (micro) to 108 (hyperscale) at 110 pods per node; each EKS tier now states that limit.
- **The OpenAPI schema matches the server's validation, and is valid.** `vpcCidr` was checked only for a private-looking prefix; `region`, `vpcCidr` and `deploymentName` now carry the same pattern and length limits the API enforces. The `region` property also used an `examples` map, which OpenAPI 3.0 doesn't allow in a schema, so the document failed validation; it now uses a single `example`.
- **The API docs page (`/api/docs/ui`) renders correctly in both themes.** In light mode the GET and POST badges had dark text on blue and green, and the request URL and response headers after "Execute" were white on a light background. The copy-to-clipboard icons were blank squares in both themes, because a style override erased the icon. Schema properties lost their types, with every `[...]` toggle pushed to the far right. The Servers card was wider than the cards around it, the API title and description appeared twice, `/favicon.ico` returned 404, "Controls Accept header." was dark green on dark, and focus outlines were removed, so keyboard users couldn't see where they were.
- **Text meets WCAG AA contrast (4.5:1) in both themes.** Several colors fell short: secondary text in light mode (4.49:1 on the page background, less on the footer), validation errors in dark mode (3.6:1, red on the dark card), button and badge text in dark mode (3.6:1, white on light blue), and the subnet table's status message (Tailwind's green-600, 3.3:1 on a white card; the copy confirmation icon was green-500, 2.3:1). Light-mode `--muted-foreground` is slightly darker, dark-mode `--destructive` is a lighter red, dark-mode text on primary and destructive surfaces is now dark, and a new `--success` token (5.6:1 light, 9.8:1 dark) replaces the fixed greens, in the app and on the API docs page. Error toasts keep their look through new `--destructive-soft` tokens. `tests/unit/ui-styles.test.ts` reads the colors from `index.css`, checks every text pair the app renders, and fails on any Tailwind palette color (`text-green-600`, `bg-gray-50`) in client code, which bypasses the theme. It used to check hard-coded values, one of which didn't match the stylesheet, and the design docs quoted ratios (7.2:1, 12.5:1) the palette never had.
- **The 404 page follows the saved theme.** Only the calculator applied the theme, so the 404 page was always light; it also used fixed grays that would have left its heading dark on dark. The theme is now applied before the first render on every page, and the 404 page uses theme tokens.
- **The theme toggles say what they do.** Both the calculator's and the API docs page's toggle were named "Toggle dark mode" in either theme. They now read "Switch to light mode" or "Switch to dark mode", updated on every change.
- **The calculator works when browser storage is blocked.** Reading the saved theme threw where `localStorage` is unavailable (all cookies blocked, some private modes), and the error page replaced the calculator. Storage errors now fall back to the light theme, as on the API docs page.
- **The calculator works from the keyboard and with screen readers.** The copy buttons in each row stayed invisible when focused (and on touch screens); they now show on focus and on coarse pointers. Split, remove and Reset unmounted the button that was pressed and dropped focus to the page; focus now moves to the affected row's checkbox (Reset: the input), which has no tooltip to pop up and can't repeat a split under a held Enter. Status messages ("Successfully split subnet...") sit in a live region, a failed Calculate's error is an alert that is read every time it fails (focus stays where it was), and the example buttons announce "Subnet calculated" instead of changing the page silently. The toast close button has a name, error toasts stay 8 seconds instead of 2, buttons whose spoken name didn't contain their visible text ("Hide Parents", "Export CSV") use the visible text, pinch zoom is no longer disabled, and the empty state heading is an `h2` after the `h1`.
- **Controls are easier to see.** Input borders were 1.4:1 against the card in light mode and 1.6:1 in dark mode; they are now above 3:1 (WCAG 1.4.11). Buttons had a 1px focus ring in the button's own color, which vanished on primary buttons; it is now 2px with a gap. The header icons (API docs, theme) render at their intended 20px: the button's 16px icon rule overrode their size classes.
- **The calculator fits a 320px-wide screen.** The network overview's two columns overlapped for large networks (a /0 has 4,294,967,296 addresses), and the subnet table's toolbar (Hide Parents, Export CSV) ran off the side. The overview stacks into one column on phones, and the toolbar wraps; only the table itself scrolls sideways.
- **The calculator loads over plain HTTP on a LAN address.** Helmet's default CSP includes `upgrade-insecure-requests`, so browsers fetched the app's own scripts and styles over https from a server that speaks only HTTP, and the page stayed blank. The directive is no longer sent; TLS, where used, is terminated in front of the server.
- **Only content-hashed build files are cached for a year.** Any file whose name ended in a hyphen and eight or more characters counted as hashed, so `subnet-splitter.png` and `github-nicholashoule.png` were cached `immutable` and a replaced image never reached returning visitors. Only the files Vite writes to `assets/` are cached that way now; everything else revalidates.
- **Selection counts only visible rows.** After removing a split or hiding parents, selected rows that were no longer shown still counted: Export CSV could read "(2)" and download a file with no rows, and the select-all box showed checked with rows unselected. The count, the export and the select-all box (now with a partial state) use the rows on screen.
- **Borders follow the theme.** Elements with a border but no border color (table row dividers, tooltips, toasts) used a fixed light gray, which glared in dark mode; they now use `--border`. Native scrollbars and form controls follow the theme too (`color-scheme`).
- **Smaller calculator fixes.** The Split button is hidden on subnets that are already split, where it did nothing. Status and copy-confirmation timers restart instead of an earlier timer clearing a newer message early. Rows no longer re-render on every toast.
- **Rejected API requests are logged.** Request logging was registered after the body parsers, so malformed or oversized bodies (400, 413) never reached the request log: exactly the traffic worth seeing. It now runs first, ahead of the new API rate limiter, so rate-limited requests (429) are logged too; health probes are still skipped.
- **Unknown API paths get a JSON 404.** In production a mistyped path or method (`GET /api/typo`, or `GET /api/k8s/plan`, which only accepts POST) fell through to the web app and returned `index.html` with a 200, so a Terraform `http` data source failed in `jsondecode` with a confusing error; each one also counted against the page-load rate limit. Other methods got Express's HTML error page. Every unmatched `/api` request now answers `404` with `{"code": "NOT_FOUND"}`. The error handler moved after static serving and Vite, so their errors are handled too.
- **A repeated `format` parameter no longer causes a 500.** `?format=json&format=yaml` parses as an array, and the plan, tiers and OpenAPI routes crashed on it. A value that isn't a single string now means JSON.
- **YAML output reads back the same in every YAML version.** A `region` or `deploymentName` of `no`, `yes`, `on` or `off` was written unquoted, and YAML 1.1 readers such as PyYAML loaded it as `false` or `true`; a YAML 1.2 reader loads a value like `0o17` as a number. Every string value is now double-quoted (keys stay plain), so `deploymentSize: "micro"` replaces `deploymentSize: micro`; parsed values are unchanged.
- **Bad `PORT` and `TRUST_PROXY` values stop startup with a clear message.** `TRUST_PROXY=true`, a value Express itself documents, crashed the server with a stack trace (now it is accepted, with a warning that any client can then set its own IP), and so did an invalid proxy address. A non-numeric `PORT` failed with misleading "unhandled rejection" and "error during shutdown" logs, and `5000abc` was read as `5000`.
- **Miscased API paths are logged.** Routing ignored case but request logging did not, so `/API/K8S/PLAN` was served but never logged. API paths are now lowercased before anything else sees them (the query string keeps its case), so `/API/K8S/PLAN` is served, logged and rate limited exactly like `/api/k8s/plan` (the log keeps the client's spelling as `requestedPath`), and `/API/V1/HEALTH` is exempt like any health probe. The health checks answer in any letter case too, so a probe at `/HEALTH` gets the health response, not the web app. This also holds for the absolute-form request targets proxies send (`GET http://host/API/...`). Other routes match case-sensitively.
- **The OpenAPI document lists every response.** `429` (with its `RateLimit-*` and `Retry-After` headers), YAML error bodies, and the `NOT_FOUND` code were missing.
- **Dismissed toasts leave memory after a second**, not 16 minutes.

### Security
- **The build no longer depends on `braces`.** A high-severity advisory (GHSA-vfj7-8cjw-p6xm, stack exhaustion from deeply nested patterns) covers every published version of `braces`, which Tailwind CSS 3 pulled in through its file watcher and glob libraries, so `npm audit` failed with no patch to apply. Tailwind CSS 4 doesn't use it. Only build tooling was affected; neither shipped bundle contained it.
- **The web app no longer allows scripts from cdn.jsdelivr.net.** jsDelivr serves any npm package or GitHub file, so allowing it on every page let an injected `<script>` load arbitrary code despite `script-src 'self'`. Only the Swagger UI page (`/api/docs/ui`) allows it now. `connect-src` also drops the Google Fonts origins, which it never needed, and both pages drop their preconnect hints to them, so no page asks to connect anywhere the policy doesn't allow.
- **The API docs page keeps `form-action 'self'` and `script-src-attr 'none'`.** Its CSP replaced the global header with one built from a directive list that lacked both of Helmet's defaults, so the one page allowing a CDN and inline scripts also allowed inline event handlers and form posts anywhere.
- **Swagger UI assets are pinned and integrity-checked.** The page loaded the floating `swagger-ui-dist@5` tag with no integrity check. It now loads `5.33.1` with sha384 Subresource Integrity, so a changed CDN file is refused.
- **The API is rate limited.** `/api` routes allow 100 requests per minute per IP and answer `429` with `{"code": "RATE_LIMITED"}` and `RateLimit-*` headers. Health probes (`GET` or `HEAD` of `/health`, `/health/ready`, `/health/live` and their `/api/v1` aliases) are exempt so they never fail. Before, plan generation had no limit. The limit runs before the JSON parser, so malformed or oversized bodies count toward it; the development CSP report endpoint's limiter also moved ahead of its parser. `GET` and `HEAD` bodies are never parsed, so a health probe (exempt from the limit) with a junk body can't produce unthrottled errors and log lines.
- **Request input is bounded.** Bodies are capped at 16 KB (was 100 KB). `region` must be lowercase letters, digits and hyphens (64 characters at most), since it is written into zone names that end up in Terraform; `deploymentName` is capped at 128 characters. A request with `"region": "US-EAST-1"` now gets a 400.
- **500 responses no longer echo internal error messages.** The global error handler returned `err.message` for every failure. Client errors (malformed JSON, oversized bodies) are now logged as warnings, not errors.
- **Logs and error responses no longer repeat request bodies.** A plan request that failed with a 500 was logged with its raw body, including any field a client added and the free-text `deploymentName`. The log now records an allowlist of the validated fields that determine the plan, enough to reproduce the failure. Rejected bodies (400, 413, 415) are logged with body-parser's error type instead of its message, which can quote part of the body, and the response carries fixed text for that type ("Request body is not valid JSON") instead of the message.
- **The dev server's DNS-rebinding protection is back on.** `allowedHosts: true`, needed only for Replit's proxied hostnames, turned off Vite's Host header check.
- **The package is marked `private`**, so it cannot be published to npm by accident.

### Added
- **Private network mode** (`"networkMode": "private"`). The plan has no public subnets; `subnets.loadBalancer` holds internal load-balancer subnets instead, and egress is expected through a managed NAT or gateway that takes no space in the layout. GKE gets one regional proxy-only subnet (`REGIONAL_MANAGED_PROXY`, needed for internal Application Load Balancers and the internal Gateway; one per region and network, /26 minimum) and Cloud NAT for egress. AKS gets one regional internal load-balancer subnet and a NAT gateway or user-defined routes for egress. EKS gets internal load-balancer subnets in at least two AZs (tag `kubernetes.io/role/internal-elb`), and reaches the internet through a transit gateway to an egress VPC, or not at all with VPC endpoints: a public NAT gateway needs a public subnet, and a private one can't reach the internet. Plans now always include `networkMode` and `subnets.loadBalancer` (empty in public mode), and `/api/k8s/tiers` takes `?networkMode=`.
- **`podsCidr` and `servicesCidr` request fields.** Every plan whose VPC is in the same RFC 1918 block got identical pod and service ranges, so a second cluster in the same GCP network (where secondary ranges must not collide), or in a peered network, overlapped the first. Supply your own ranges to keep clusters apart or to keep an existing cluster's service range. Pods may use RFC 1918 or `100.64.0.0/10` at /8 to /24; services RFC 1918 at /13 to /24 (EKS allows /12-/24, AKS requires smaller than /12). Neither may overlap the VPC, each other, or `172.17.0.0/16`.
- **`availabilityZones` request field.** Generated EKS zone names follow `{region}{letter}`, but which letters exist varies by region and account: `ap-northeast-1b` doesn't exist for new accounts. Pass the zones your account has (e.g. from `data.aws_availability_zones`); they are assigned round-robin. EKS needs at least two; GKE and AKS reject the field because their subnets are regional.
- **`warnings` in the plan**, listing non-fatal issues such as a VPC that overlaps `172.17.0.0/16`. Omitted when empty.
- **`provider` query parameter on `/api/k8s/tiers`.** 1.0 ignored any query; an unknown `provider` or `networkMode` value is now a `400`.
- **`HOST` environment variable.** Production now binds `0.0.0.0` by default, so the server is reachable inside a container; development binds `127.0.0.1`. Set `HOST` to override either.
- **CI checks the production build, not just the source.** `npm run smoke` (`scripts/smoke-test.ts`) starts `dist/index.cjs` (refusing to run if something already answers on its port, and failing if the bundle exits mid-run) and checks it over HTTP: health and version, the web app with its CSP, security and caching headers, the SPA fallback, the plan and tiers APIs (private mode, validation errors, rate-limit headers), JSON 404s for unknown API paths, the API docs page's pinned assets (it downloads them and checks their SRI hashes against the bytes the CDN serves; `SMOKE_SKIP_CDN=1` skips the download offline, and CI ignores it), and that a bad `PORT` or `TRUST_PROXY` stops startup. CI then validates the served OpenAPI document with `swagger-cli`, which would have caught the invalid `region` schema this release fixes. The CI job also has a 15-minute timeout.
- **A pre-commit hook checks for emoji.** `npm install` sets `core.hooksPath` to `.githooks/` (unless a hooks path is already set, say for gitleaks or husky; then it prints how to opt in) (the `prepare` script never fails an install, even in a container build that copies `package*.json` first). The POSIX `sh` hook, which runs on Windows through Git for Windows, macOS and Linux, exports the staged files to a temporary directory and runs `npm run emoji:check` there, so it stops a commit that adds emoji while unstaged edits and untracked files never block one. Without Go 1.24 or newer, or when demojify cannot be downloaded or built, it says why and lets the commit through, since CI runs the same check.
- **OpenAPI examples are generated by the API itself** at startup, and a test checks each one against a live request, so they can't drift from real output again.

### Changed (project)
- **The API docs page uses the web app's palette and fonts.** One set of color tokens, copied from the app and redefined for dark mode, replaces separate light and dark style sheets that had drifted apart (the version badges even swapped colors between themes). A test fails if the page stops matching the app. Method badges use fixed, readable colors, operations carry a method-colored edge, and text is Inter and JetBrains Mono, as in the app. Toggling the theme re-renders the page in place instead of reloading it. The page now lives in `server/swagger-ui.ts`, taking about 1,100 lines out of `server/routes.ts`, and operations have explicit `operationId`s, so deep links such as `#/Kubernetes/generateNetworkPlan` work without Swagger deprecation warnings.
- **Tailwind CSS 4, through its Vite plugin.** Tailwind's Rust engine (Oxide to scan sources, Lightning CSS to add prefixes and minify) replaces the PostCSS and autoprefixer pipeline. The theme moves from `tailwind.config.ts` into `client/src/index.css` (`@theme inline`), and `tw-animate-css` replaces the `tailwindcss-animate` plugin. The calculator looks the same: computed styles of 18 elements in both themes match before and after, apart from one fix. The Calculate and Reset buttons now line up with the input at 48px. They were 56px and started 8px above it, because Tailwind 3's `space-y` added a margin before the input's hidden label, and they stretched further when a validation error showed. The CSS bundle grows from 33.6 to 41.3 KB (7.1 to 8.4 KB gzipped), from v4's registered custom properties and theme variables.
- **The package is named `subnet-splitter`** (was the template's `rest-express`), at version 2.0.0. `/health`, `/api/version` and the OpenAPI document report the version from `package.json` instead of a hard-coded `1.0.0`.
- **Validation errors name the field.** A bad request answers `"Invalid request: deploymentSize: Required"` instead of a JSON dump of the validator's issue list. At most 5 issues are listed, then "and N more", so a 16 KB body of bad array entries can't produce a response hundreds of KB long.
- **Generated VPCs vary more.** A random VPC can be any aligned /18 in its block, not only `10.N.0.0/18` or `172.N.0.0/18`.
- **The web app downloads less.** JavaScript is 271 KB (88 KB gzipped), down from 371 KB (116 KB), and the unused Fira Code font is no longer requested.
- **`npm start` runs `node dist/index.cjs`**, which works in cmd and PowerShell as well as POSIX shells. The build already bakes in `NODE_ENV=production`.
- **Logs are quieter.** Health probes and response bodies are no longer logged per request, and startup lists routes at debug level.
- **The no-emoji rule is enforced by [demojify-sanitize](https://github.com/nicholashoule/demojify-sanitize)** v1.1.0, as its own CI job (Go) and through `npm run emoji:check` and `npm run emoji:fix`. It replaces an in-repo checker that missed emoji on every other line (a global regex reused with `.test()`), scanned paths that don't exist without noticing, and had tests that never ran detection.
- **The development CSP violation endpoint lives in `server/csp-report.ts`**, so its tests exercise the real handler and limiter instead of a copy.

### Removed
- **Form-encoded request bodies.** The API reads JSON only. 1.0 also parsed `application/x-www-form-urlencoded`, so `curl -d deploymentSize=micro` returned a plan; that request now gets a `400` (`"Invalid request: Required"`). Send `Content-Type: application/json`.
- **Replit support**: `.replit`, the three `@replit/vite-plugin-*` dev plugins, the Replit CSP origins, `REPL_ID` handling, the `@assets` alias, and the `127.0.0.1`-then-`localhost` bind fallback.
- **Unused dependencies**: `react-hook-form`, `@hookform/resolvers`, `wouter`, `@radix-ui/react-label` and `cross-env` (29 packages leave the install). The calculator's single input no longer needs a form library, and its two pages no longer need a router.
- **The API docs page's repaint script and 268 KB topbar preset.** A MutationObserver re-applied inline colors after every render and click; Swagger's own light and dark highlight themes now do that job. The page no longer downloads `swagger-ui-standalone-preset.js`, whose topbar it hid anyway.
- **The Tailwind CSS 3 toolchain**: `postcss`, `autoprefixer`, `tailwindcss-animate`, `tailwind.config.ts` and `postcss.config.js`, plus theme tokens nothing used (chart, sidebar and status colors, accordion animations, the toggle-elevate classes, and shadow, radius and spacing variables the old config never read).
- **The `test:ui` script**, which needed `@vitest/ui` and never worked. Also unused code: `server/storage.ts` and the `form` and `label` components.
- **The in-repo emoji checker**: `tests/unit/emoji-detection.test.ts`, `tests/helpers/emoji-config.ts`, `scripts/fix-emoji.ts` and the `test:emoji` script.
